# HTML 报告规范

## 目标

生成一份单文件 HTML，让读者能从“研究范围”一路追溯到“产品机会”和“原始素材”。报告服务决策，不追求装饰性图表。

## 固定结构

1. **研究范围**：主题、目标用户、地区/平台、日期、研究问题、来源数量、访问限制。
2. **执行摘要**：最多三句话，分别写主要发现、最大机会、最大风险。
3. **证据质量**：解释 E0/E1/E2/E3 的含义，并显示事实、推断、假设的数量。
4. **优先级矩阵**：频率 × 强度；点的旁边显示痛点名称、评分、置信度和素材 ID。
5. **痛点簇**：场景、后果、替代方案、代表性原话、反例、证据链接。
6. **竞品盲区**：竞品/替代方案 × 痛点簇；每个单元格用“已覆盖 / 部分覆盖 / 未见证据”。
7. **产品机会**：最多 3 个，每个包括用户、场景、价值、最小方案、风险、验证问题和素材 ID。
8. **原始素材**：可折叠列表，显示 ID、来源状态、摘要、原文、URL、时间和互动量；未知字段明确写“未知”。
9. **下一步**：建议访谈、原型或进入 BRD/MRD 的动作。

## 数据表示

先在模型内部整理结构化数据，再填入 HTML。可使用以下字段：

```json
{
  "research": {"topic": "", "audience": "", "scope": "", "date": "", "limitations": []},
  "materials": [{"id": "R01", "source": "Reddit", "evidence": "E2", "url": "", "summary": "", "quote": "", "tags": [], "emotion": 3}],
  "clusters": [{"name": "", "material_ids": [], "frequency": 3, "intensity": 4, "confidence": "中", "counterevidence": ""}],
  "opportunities": [{"rank": 1, "name": "", "users": "", "mvp": "", "risks": [], "validation_questions": [], "material_ids": []}]
}
```

## 视觉与交互

- CSS 和原生 JS 全部内联，不依赖 CDN、图表库或远程图片；
- 以可读性为先：正文、证据标签和来源链接在手机上也要能看；
- 用颜色区分优先级和证据等级，但不能只靠颜色传达信息；
- 图表没有足够数据时，显示“样本不足”，不要绘制看似精确的点；
- 原始素材使用 `<details>` 折叠，避免长报告首屏信息过载；
- 外部链接使用完整 URL，并在新窗口打开。

## 报告检查

- 每个事实、引用、数字和评分都能回到素材 ID；
- 没有把 E0/E1 线索标成用户原话；
- 访问限制和样本偏差出现在报告正文，而不是藏在脚注；
- 文件可以离线打开，HTML 标签闭合，移动端不横向溢出正文；
- 报告结论区分“现在知道”“推断得到”“下一步要验证”。
