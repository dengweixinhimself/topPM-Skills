# topPM-Skills

面向 AI 产品经理的可复用 skill。当前仓库先提供一个经过重构的 **产品机会调研** skill：

[`product-insight-miner/`](./product-insight-miner/)

它把公开资料、用户手动提供的帖子/评论/截图和竞品信息，整理成可追溯的用户痛点、需求优先级、竞品盲区和产品机会报告。

## 这版优化了什么

本版本基于 [chusimin/AIPM-Skills](https://github.com/chusimin/AIPM-Skills) 的 `product-insight-miner` 重写，保留原有研究框架，同时修正了实际使用中最容易失真的部分：

- **工具无关**：不再假设环境一定有 `web_search` 或 `web_fetch`，会使用当前可用的搜索、浏览器或连接器；
- **证据分级**：区分搜索线索、官方页面、原帖和多来源交叉验证；
- **禁止伪引用**：搜索摘要不能冒充用户原话，官方能力不能冒充用户满意度；
- **事实与假设分离**：报告明确区分“现在知道”“推断得到”“下一步验证”；
- **更适合中文研究**：加入中英混输、场景、竞品迁移、隐私和应用商店反馈等研究角度；
- **交付路径可移植**：HTML 默认写入当前工作区的 `outputs/`，不依赖固定的 `/mnt/user-data/outputs`；
- **减少无效搜索**：用两轮搜索和停止条件控制范围，避免无止境堆链接；
- **支持手动投喂**：平台访问受限时，可直接粘贴文字、链接或截图继续研究；
- **支持产品决策链**：调研结果可以继续交给 BRD、MRD 或 PRD skill。

## 安装

### Codex

把 `product-insight-miner` 文件夹复制到：

```text
~/.codex/skills/product-insight-miner/
```

或者把整个仓库放到工作目录，再在 Codex 中显式调用：

```text
$product-insight-miner
```

安装后开启新对话，或重新加载 skills。

### Claude Code / Claude Desktop

把同一个文件夹复制到 Claude 使用的 skills 目录：

```text
~/.claude/skills/product-insight-miner/
```

不同客户端的 skills 目录可能不同，以客户端文档为准。skill 本身不要求固定的搜索服务；能否访问某个平台取决于当前客户端和连接器。

## 怎么用

直接用自然语言描述研究目标即可：

```text
帮我调研 AI 键盘现在有哪些用户痛点，先做全体用户的广泛扫描。
```

```text
研究 Mac / Windows 桌面端的 AI 输入工具，重点看快捷键、原地替换、隐私和付费意愿。
```

```text
我有这些 Reddit 帖子和用户原话，帮我归档、聚类并找产品机会：
[粘贴链接或原文]
```

```text
把当前调研生成单文件 HTML 报告。
```

```text
基于这次调研继续写 BRD，判断这个方向值不值得做。
```

## 推荐工作流

```text
产品机会调研 → BRD → MRD → PRD → 原型 / 开发
```

### 第一步：定义研究范围

告诉 skill：研究什么、看谁、在哪些地区/平台、已知哪些竞品。信息不全时，它会使用合理默认值并在报告中说明。

### 第二步：采集证据

可以让 skill 搜索公开资料，也可以连续补充链接、文字和截图。每条素材都会有 ID，例如 `R01`、`X02`、`H03`。

### 第三步：看中间结论

每轮会告诉你：新增了哪些证据、出现了哪些痛点、哪些平台访问失败、还缺什么验证。你可以回复“继续搜索”“补充这些素材”或“生成报告”。

### 第四步：生成报告

HTML 报告包含研究范围、证据质量、痛点聚类、优先级矩阵、竞品盲区、TOP 3 机会、原始素材和下一步验证计划。默认输出到当前工作区的：

```text
outputs/product-insight-report-<主题>-<日期>.html
```

## 证据等级

| 等级 | 含义 | 可以支持什么 |
| --- | --- | --- |
| E0 | 搜索结果摘要或未打开的线索 | 发现新关键词，不可当作原话 |
| E1 | 官方产品页、帮助文档、定价或政策 | 确认产品能力和公开承诺 |
| E2 | 可打开的用户原帖、评论或应用商店评论 | 支持用户原话和具体场景 |
| E3 | 多个独立来源或访谈交叉验证 | 支持更高置信度的痛点判断 |

报告中的频率、强度、付费意愿和机会结论都应该带素材 ID。样本不足时会明确写“待验证”，不会用看似精确的数字填空。

## 平台访问受限怎么办

小红书、X、Reddit 等平台可能需要登录、地区权限或反爬验证。遇到这种情况：

1. 让 skill 记录访问限制；
2. 继续使用官方资料、其他社区或应用商店评论交叉验证；
3. 把你看到的帖子正文、截图或链接粘贴进对话；
4. 报告中保留“已访问”和“待复核”的区别。

不要把搜索摘要当作用户原话，也不要把同一个帖子在多个搜索结果中的重复出现算成多个用户。

## 本地校验

如果安装了 Codex 的 skill-creator 工具，可以运行：

```bash
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py product-insight-miner
```

校验通过只表示目录、命名和 frontmatter 合法；真正的质量还需要用真实研究请求跑一轮，检查证据是否可追溯、报告是否诚实表达限制。

## 贡献建议

新增规则前，先确认它是否解决了真实的错误。优先补充：

- 具体平台的访问限制和证据边界；
- 可复用的数据字段或报告模块；
- 已验证的用户研究方法；
- 能减少重复搜索或虚假精确感的脚本。

避免把一次研究中的个别偏好写成所有项目都必须遵守的规则。
